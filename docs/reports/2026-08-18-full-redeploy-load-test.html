What I had to intervene on

One thing, and it's mine, not the product's:

  • Test-script bug, not a product bug: the first Azure run of bankschema failed all 88 pipes. Root cause: my own load-test driver script passed the literal string "600" as a targetType parameter (I meant it as a timeout override, but there's no CLI slot for that — it landed in the wrong argument). The app correctly rejected every single pipe with Unsupported targetType '600' — that's the input validation working as designed, not a defect. I caught it from the app logs within a minute, fixed my script, reran, and all 88 pipes succeeded immediately with no other changes.

Everything else — the new schema's DDL, the sidecar prefix map, the Compose wiring, the Terraform/K8s/monitoring wiring for Azure, the fresh destroy+apply cycle, and every one of the 406 real pipe runs across both environments — worked on the first attempt with no fixes needed.
